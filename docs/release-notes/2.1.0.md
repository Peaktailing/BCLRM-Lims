## BioManager 2.1.0 — the chemical tables, normalised

### New

- **One naming rule for the chemical domain.** Eleven tables are now `chem_` + a singular noun: `chem_course`, `chem_borrow_order`, `chem_return_record`, `chem_allocation_order`, `chem_demand`, `chem_manager_change_log`, `chem_purchase_plan`, `chem_purchase_order`, `chem_experiment`, `chem_substance` (was `chemical_references`) and `chem_controlled_list` (was `controlled_list`). The prefix groups the tables that arrived together and will be merged into the BCLRM main repo together; the singular matches that repo's own naming, so the eventual merge is a column map rather than a second rename. `notebook_recipes` keeps its name: it belongs to the notebook, not to the chemical document flow.
  - **化学域统一成「`chem_` 前缀 + 单数」**：11 张表改名，`chemical_references` 改为 `chem_substance`（它本来就是「物质主数据」，不是「参考」），`controlled_list` 改为 `chem_controlled_list`。前缀把这批表圈在一起（它们是一起进来、将来一起并入主仓的），单数与主仓一致（`borrow_order`、`reagent_demand`），合并时是列映射而不是再改一次名。`notebook_recipes` 不改：它属于笔记本域，不属于化学单据流。
- **A borrow order can hold several bottles.** `chem_borrow_order` is now the head — who asks, why, by when, who approved — and `chem_borrow_order_item` holds one row per bottle, with the amount asked for, issued and returned kept apart. One class can take three reagents on one order and one approval instead of three of each; "not issued" becomes a queryable state (`short`) rather than an inference from a count that does not add up. The head's old `bottle_id` / `quantity` / `unit` stay as the single-line form and go once the read paths move.
  - **一张领用单可以有多瓶**：单头只说谁、为什么、什么时候还、谁批的；明细一行一瓶，申请量 / 实发量 / 已还量分开记——库存不够时这三个数本来就不一样，「没领到」因此成为可查询的状态（`short`），而不是靠「单据是 borrowed 但数量对不上」去推断。单头上的旧列降级为「单瓶简式」，读路径切换后删除。
- **A bottle stops carrying everything.** The substance's CAS, formula, hazard and default purity move to `chem_substance`; a delivery's vendor, catalogue number, lot, price, pack size and expiry move to the new `chem_lot`; the custodian and the opening date, and the placement history, move to the new `chem_bottle` and `chem_placement`. The bottle itself stays a row of `inventory_items` — one number, one bottle — and every document table that points at `inventory_items.id` needs no change. Nothing is dropped: the old columns and `attrs` keys stay, `v_chem_bottle_state` shows the old flat shape, and `v_chem_borrow_order_line` turns items back into one-row-per-bottle.
  - **瓶子不再什么都扛**：物质固有属性（CAS、分子式、危险性、默认纯度/品级、密度）上移到 `chem_substance`，一次到货共享的（供应商、货号、批号、单价、包装、有效期）上移到 `chem_lot`，保管人、启封日、位置历史落到新增的 `chem_bottle` 与 `chem_placement`。瓶子仍然是 `inventory_items` 的一行（一瓶一号），所有指向它的单据表一行不改。设计依据与迁移三段式见 `docs/化学表规范与范式化设计.md`。
- **`sync_version` explained in place.** It is not server-to-server synchronisation: it is the lab-wide change counter (`app/sync_clock.py`) that lets a phone ask "what changed since I last looked" and "did this change since I read it". `chem_controlled_list` has it because a phone signing a bottle out checks the list before the shelf. The column is now documented where it is defined, and the comment says why the main repo, which has no offline device, will keep it anyway.
  - **`sync_version` 的用途写进注释**：它不是服务器之间的同步，而是实验室级的全局变更计数——手机离线时记一个游标，联网问「我上次看之后变了什么」与「我手里这份还是最新的吗」。管控名录带它，是因为手机签出一瓶试剂之前要查名录。主仓没有离线客户端，但合仓时仍保留此列（默认 0），删了会让这边的手机端读不到名录。

### Updating

- **Run the migration.** `alembic upgrade head` renames the eleven tables, adds `chem_borrow_order_item`, `chem_lot`, `chem_bottle`, `chem_placement`, widens `chem_substance` and `chem_controlled_list`, backfills every bottle's substance / delivery / placement from its columns and `attrs`, and creates the two compatibility views. It is additive: no column is dropped, and run twice it does nothing the second time. Your data is backed up first, as every upgrade is.
  - **执行迁移**：`alembic upgrade head` 改名 11 张表、建 4 张新表、给 2 张表补列、把每瓶的物质/批次/位置从旧列与 `attrs` 回填，并建立两个兼容视图。全为加法：不删任何列，重复执行不会重复写入。

### Tests

- 114 tests in the chemical domain pass (chemlib 45, chemicals 16, controlled 15, reagent workflow 10, courses 13, experiments 15), and 159 more around inventory, lookup and sync. The migration is verified on a 0049 database holding bottles: four bottles fold into three deliveries, three link to their substance, four placements are written, and a second run changes nothing.
  - 化学域 114 个测试通过，另有 159 个库存/查找/同步测试通过。迁移在含试剂瓶的 0049 库上验证：4 瓶归入 3 个批次、3 瓶关联到物质、写入 4 条位置，第二次执行计数不变。
